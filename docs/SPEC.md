> 이 문서는 Claude Code에게 전달하는 구현 지시서입니다. 프로젝트의 `docs/SPEC.md`로 두고 함께 `docs/QUALITY96.md`를 읽으세요.
> 질문하지 말고, 모호한 부분은 이 문서의 기본값으로 결정한 뒤 `DECISIONS.md`에 기록하세요.
> **작업은 §16 마일스톤 순서대로 진행하고, 한 번의 실행에서 전부 끝내려 하지 마세요.** 각 마일스톤을 `pnpm check` 통과 상태로 끝내고 `docs/PROGRESS.md`에 "다음에 할 일"을 적어 두세요. 컨텍스트가 길어지면 이 문서와 `PROGRESS.md`를 다시 읽고 이어서 진행합니다.
> **수직 슬라이스 우선**: M0~M4(허브 + 교육 엔진 + 스테이지 3개)가 실제로 돌아가고 재미있는지 확인한 뒤 나머지를 확장하세요.

## 0. 역할과 작업 방식

당신은 (1) 시니어 웹 그래픽스·게임 엔지니어, (2) 초등 저학년 수학 교육 설계자, (3) 어린이 UX 디자이너를 겸합니다.

- 한국어 UI, 영어 코드 식별자. 사용자 대면 문자열은 전부 `src/i18n/ko.ts` 한 곳에서 관리(타입 안전 키).
- 이 문서의 모든 항목은 **요구사항**입니다. 구현 못 한 항목이 있으면 `docs/GAPS.md`에 이유와 대안을 적으세요.
- 구현 시작 직후 `docs/PROGRESS.md`를 만들고 마일스톤(§16)마다 갱신하세요.
- 의존성 버전은 문서에 적지 않았습니다. **설치 시점에 `npm view <pkg> version`으로 최신 안정(stable) 버전을 확인해 고정**하세요. alpha/beta/RC는 사용 금지.
- 라이브러리 API는 기억에 의존하지 말고 설치된 버전의 공식 문서/예제를 1차 근거로 삼으세요(특히 three.js `webgpu_*` 공식 예제).

### 0.1 Claude Code 운영 방식 (이 프로젝트의 실행 규칙)

1. **시작**: 이 문서와 `docs/QUALITY96.md`를 읽고, 첫 응답에서 M0~M4(Gold Slice) 계획을 10줄 이내로 제시한 뒤 곧바로 M0을 시작하세요(Plan 모드로 실행 중이면 승인 후 진행).
2. **CLAUDE.md**: M0에서 루트에 `CLAUDE.md`를 만드세요(120줄 이내): 프로젝트 한 줄 설명, 불변 원칙 P1~P10 요약, `pnpm` 명령어(dev/build/check/check:score/bench), 폴더 구조, 레이어 경계 규칙, "큰 문서는 필요한 § 만 읽기", 사용자 보고는 한국어. **이 문서 전체를 CLAUDE.md에 붙여 넣지 마세요**(매 세션 컨텍스트 낭비).
3. **컨텍스트 관리**: 마일스톤이 끝날 때마다 ① `pnpm check` ② `docs/PROGRESS.md`에 "완료/다음 할 일/결정/막힌 점" 갱신 ③ 커밋 ④ 컨텍스트가 길어졌으면 `/compact` 또는 새 세션. 새 세션은 `CLAUDE.md` + `PROGRESS.md` + 해당 § 만 읽고 이어갑니다. 큰 파일을 통째로 반복해서 읽지 말고 grep·부분 읽기를 쓰세요.
4. **서브에이전트(리뷰 전담)**: M0에서 `.claude/agents/`에 읽기 전용 리뷰어를 만드세요. 각 파일은 YAML frontmatter(`name`, `description`, `tools: Read, Glob, Grep, Bash`)와 본문(시스템 프롬프트)으로 구성합니다.
   - `adversarial-reviewer`: "이 프로젝트에 투자하면 손해를 보는 입장"에서 치명적 결함과 점수 부풀림을 찾음(QUALITY96 §6, SPEC §16.1).
   - `art-reviewer`: 스크린샷을 `Read`로 직접 보고 `ART_BIBLE.md` 기준으로 아이 눈높이에서 비평(QUALITY96 §4.4).
   - `curriculum-checker`: 문제 생성기 출력 샘플을 교과 밴드 표(§9.1)와 대조.
   새로 만든 `agents/` 디렉터리는 **세션을 재시작해야 로드될 수 있습니다.** 로드되지 않았으면 같은 지시문을 general-purpose 서브에이전트에게 직접 전달해 쓰고, `PROGRESS.md`에 "재시작하면 전용 에이전트 사용 가능"이라고 적으세요. **구현자가 자기 결과물의 점수를 직접 확정하지 말고 채점은 리뷰어에게 맡기세요.**
5. **스킬/커맨드(선택)**: 반복 작업은 `.claude/skills/<이름>/SKILL.md`로 만드세요(예: `score` — `pnpm check:score` 실행 후 `SCORECARD.md` 갱신, `disable-model-invocation: true`).
6. **시각 검증**: Playwright로 스크린샷을 찍고 `Read`로 직접 보면서 고치세요. 실행 환경에 GPU가 없으면 WebGPU 경로와 실제 프레임 성능은 측정할 수 없습니다. 그 경우 WebGL2 경로(`?renderer=webgl`)로 기능을 검증하고, WebGPU 실기·프레임 타임 항목은 사용자 기기에서 돌릴 `pnpm bench`(결과 JSON 출력)와 `docs/HUMAN_INPUT.md` 입력란을 준비하세요. 이런 항목은 사용자가 결과를 붙여 넣기 전까지 점수가 인정되지 않습니다(QUALITY96 §0-5).
7. **병렬화**: 스테이지는 독립 플러그인이므로, Gold Slice 템플릿(③ ① ④)이 확정된 뒤 나머지 5개는 서브에이전트에 나눠 병렬로 구현할 수 있습니다. 공유 코드(`engine/`, `domain/`) 수정은 한 곳에서만 하세요.
8. **보고**: 사용자에게는 한국어로 짧게. 마일스톤 완료 시 "무엇이 됐고, 점수가 어떻게 바뀌었고, 사람이 해야 할 일"만 알립니다.
9. **권한·안전**: 자신의 권한 설정 파일을 수정하지 마세요. 대량 삭제 같은 파괴적 명령은 쓰지 마세요. 패키지 설치는 `pnpm`으로만 합니다.

## 1. 제품 정의

| 항목 | 내용 |
|---|---|
| 가칭 | 숫자섬 탐험대 (이름은 상표 충돌 확인 후 변경 가능) |
| 대상 | 초등 1학년 2학기(한국 나이 8세, 만 6~7세) → 2학년 2학기까지 성장하며 사용 |
| 학습 목표 | 덧셈·뺄셈 (1학년 2학기 기준에서 시작, 2학년 2학기 수준까지 확장) |
| 플랫폼 | 데스크톱 웹(Chrome/Edge/Firefox/Safari 최신) 1순위, 터치 태블릿 2순위. PWA 설치·오프라인 지원 |
| 스타일 | 캐주얼 3D 장난감 디오라마(말랑한 젤리·클레이 질감, 파스텔, 부드러운 그림자) |
| 한 판 | 2~4분(스테이지당 퍼즐 8개 또는 5라운드). 15분마다 "쉬어요" |
| 핵심 구조 | **3D 숫자섬 허브**에서 8개 스테이지를 지도 고르듯 **자유 선택** (처음부터 전부 해제) |
| 네트워크 | **없음.** 온라인 기능·계정·광고·결제·분석 전송 전부 금지 |

### 1.1 스테이지 8종 (사용자 확정, 이름 변경 금지)
막고 부수는 게임: ① 폭탄 해체반 ② 좀비 숫자 막기
모으고 맞추는 게임: ③ 숫자 낚시 ④ 슬라임 합체 ⑤ 이상한 자물쇠 방탈출
같이 하는 게임: ⑥ 피자 가게 둘이서 ⑦ 숫자 카드 배틀 ⑧ 정답 달리기 레이스

### 1.2 세계관 (3문장, 무섭지 않게)
숫자섬의 괴물 친구들이 숫자 구슬을 잃어버렸어요. 탐험대원(아이)이 8개 지역을 돌며 숫자를 맞춰 구슬을 되찾아 주면, 괴물 친구가 늘어나고 섬이 커져요. 모든 지역의 문제는 "친구를 돕는 일"로 연결됩니다(실패해도 친구가 웃으며 다시 해보자고 함).

### 1.3 감성 레퍼런스 (감성만 차용, 모방 금지)
- 로블록스풍: 내 아바타를 꾸미고, 섬 허브를 직접 돌아다니고, 코스를 달리는 자유로운 느낌.
- 브롤스타즈풍: 1~3분 짧은 매치, 캐릭터마다 개성, 트로피로 오르는 랭크.
- 위 게임들의 이름·캐릭터·UI·소리·형상을 따라 하지 않는다(P3). 아래 §12의 아바타·트로피·탐험대원이 이 감성을 담당한다.

## 2. 기술 현황 (2026-10-15 검색 확인 / 구현 시 재확인)

**확인된 것**
- Three.js `WebGPURenderer`는 `three/webgpu`에서 가져오고 셰이더는 TSL(`three/tsl`)과 노드 머티리얼로 작성한다. 공식 문서는 `forceWebGL: true` 옵션으로 WebGL2 백엔드 강제를 안내하며, WebGPU가 없으면 WebGL2로 폴백하는 범용 렌더러로 설계되어 있다. (threejs.org/manual/en/webgpurenderer)
- Three.js 쪽은 WebGPURenderer에 개발이 집중되고 있고, 기존 `WebGLRenderer`는 유지되지만 큰 신기능 추가 계획이 없다고 공식 문서가 밝힌다.
- WebGPU는 2026년 기준 주요 브라우저가 지원한다: Chrome/Edge 113+, Firefox 141+(Windows, macOS ARM64는 145+라는 자료가 있음), Safari 26+(macOS/iOS/iPadOS). 단 구형 기기·드라이버 때문에 WebGL2 폴백은 필수. (web.dev 요약 기사, cinevva 가이드)
- Vite 8이 2026-03-12 안정판으로 출시, Rolldown(Rust 번들러)이 기본 번들러. Rolldown 1.0은 2026-05 안정화. (vite.dev, voidzero.dev)
- Vite+(Vite·Vitest·Oxlint·Oxfmt 통합 CLI)는 2026-03 **alpha** 발표 → alpha이므로 사용하지 않는다.

**구현 시 직접 확인할 것** (문서에 버전을 적지 않음): three 최신 안정판, React/Tailwind/TypeScript/Vitest/Playwright/Zustand/Motion 최신 안정판, `vite-plugin-pwa`의 Vite 8 호환, Pretendard 패키지 라이선스(OFL) 및 woff2 번들 방식.

## 3. 불변 원칙 (위반 시 실패)

- **P1 아이 안전**: 광고·결제·채팅·계정·외부 통신·원격 분석 없음. `fetch/XHR/WebSocket/외부 CDN/외부 폰트` 금지. 빌드 후 `tools/check-offline.mjs`가 번들 내 외부 URL을 검사해 실패시킨다.
- **P2 벌칙 없음**: 코인·도감·점수를 깎거나 삭제하지 않는다. 오답은 웃긴 연출 + 학습 피드백 + 무한 재도전. 연속 실패 시 자동으로 쉬운 문제 + 힌트 제안.
- **P3 오리지널**: 실존 게임·캐릭터·밈·브랜드의 이름·형상·소리를 쓰지 않는다. 모든 3D 모델은 **코드로 생성(프로시저럴)**, 사운드는 **WebAudio 합성**이 기본. 이미지(일러스트·아이콘·텍스처)는 `docs/QUALITY96.md` §4.2의 경로(사용자 제공 오리지널 → 연결된 이미지 생성 도구 → SVG/프로시저럴)로 사용하고, CC0/퍼블릭도메인 에셋은 출처 기록 시 허용(충돌 시 QUALITY96 우선).
- **P4 글 최소화**: 핵심 정보는 숫자·그림·소리·색/모양. 문장은 짧게(한 줄 12자 이내 권장), 모든 안내에 🔊 읽어주기(Web Speech `ko-KR`).
- **P5 권위 있는 규칙, 장식용 물리**: 게임 판정은 결정론적 순수 규칙으로 한다. 물리(Rapier 등)는 시각 연출 전용이며 판정에 영향 주지 않는다.
- **P6 결정론**: 시드 RNG + 고정 타임스텝(60Hz) → 같은 시드·같은 입력이면 같은 결과(리플레이 테스트 가능).
- **P7 로컬 데이터**: IndexedDB만 사용, 내보내기/가져오기 제공. 개인정보는 별명만.
- **P8 성능**: 2020년대 노트북 내장 GPU에서 1080p 60fps 목표, 최저 30fps 보장(품질 자동 조절, §7.2).
- **P9 접근성**: 키보드·마우스·터치·게임패드 모두로 전 기능 조작 가능, 색 외 모양 이중 인코딩, 모션 감소·고대비 지원.
- **P10 한 판 짧게**: 어떤 상태에서도 "다시 하기/나가기"가 즉시 가능.

## 5. 기술 스택 (최신 전용, 사용자 선호 반영)

| 영역 | 선택 |
|---|---|
| 언어 | TypeScript 최신 안정판, `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` + `verbatimModuleSyntax`. `any` 금지 |

### 6.3 게임 루프
- 고정 타임스텝 60Hz 시뮬레이션 + 렌더 보간. 누적 시간 상한(스파이럴 방지). 탭 비활성 시 일시정지.

## 7. 렌더링 설계

### 7.1 비주얼 룩 (캐주얼 3D 디오라마)
- 스테이지마다 "책상 위 미니어처 디오라마": 고정 카메라(약 35~45° 하이앵글, 살짝 패럴랙스), 파스텔 팔레트, 두꺼운 둥근 형태.
- 머티리얼: 툰+소프트 셰이딩 하이브리드 `NodeMaterial`(림라이트, 부드러운 램프 램프), **젤리 머티리얼**(프레넬 + 서브서피스 흉내 + 버텍스 스쿼시/스트레치 스프링), **물 머티리얼**(TSL 노이즈 파동·굴절 흉내·거품 라인).
- 포스트: 약한 블룸, 노멀/깊이 기반 아웃라인(또는 인버티드 헐), 틸트시프트 DOF, 비네트, 톤매핑(AgX/ACES 중 시각 비교 후 택1, `DECISIONS.md`).
- 조명: 절차적 그라디언트 하늘 + 키라이트 1 + 필 1, 부드러운 그림자(PCF soft/VSM 중 성능 비교 후 택1).
- 에셋: 지오메트리는 `RoundedBox`·캡슐·라디얼·노이즈 변위 구체 등으로 코드 생성. 장식 다양성은 파라미터 조합으로.

### 7.2 품질 티어 & 폴백
| 티어 | 조건 | 내용 |
|---|---|---|
| Ultra | WebGPU + 충분한 프레임 여유 | 전체 포스트, compute 파티클 5만+, 부드러운 그림자 |
| High | WebGPU | 포스트 일부, 파티클 2만 |
| Balanced | WebGL2 백엔드 | **compute 불가 → CPU 인스턴스 파티클 폴백**, 포스트 최소 |
| Low | 저사양 | 포스트 없음, DPR 1, 그림자 단순 |
- 프레임 타임 EMA로 자동 상/하향(히스테리시스), DPR 상한 1.5(설정 가능), 설정에서 수동 고정 가능.
- 백엔드 판별은 설치 버전이 제공하는 공식 속성으로 하고, compute·일부 노드는 WebGL2 백엔드에서 동작 안 할 수 있으니 **기능 감지 후 대체 경로**를 둔다. 디버그 HUD(`?debug=1`)에 백엔드·티어·프레임 타임·드로콜 표시.

### 7.3 숫자 렌더링 (가독성 최우선)
- `OffscreenCanvas`로 숫자 아틀라스(0–9, +, −, =, □, ?)를 부팅 시 생성(`tools/gen-digit-atlas.ts`와 동일 로직) → 인스턴스 빌보드 쿼드 + 아웃라인.
- 3자리·4자리 수는 자릿값 색으로 칠한다(**전역 규칙**): 일=초록, 십=파랑, 백=보라, 천=금색. 색 외에 점·선·별 등 모양 패턴도 함께 쓴다(색각 이상 대응).
- 화면 속 큰 숫자는 3D 빌보드, 보조 정보(점수·타이머류)는 React HUD.

### 7.4 파티클·연출(주스)
- 색종이·반짝이·먼지·물방울을 하나의 파티클 시스템 API로 통일(`emit(kind, pos, count)`), 백엔드에 따라 GPU/CPU 구현 선택.
- 스쿼시&스트레치(임계 감쇠 스프링), 히트스톱(30~60ms), 아주 약한 카메라 셰이크, 정답 연속 시 점진적 연출 상승.
- 숨은 폭죽: 피연산자 조합이 (6, 7)이면 13 폭죽 보너스 연출(트렌드 요소, 가볍게).
- 정답 댄스(연속 정답 보상) + 선택 기능: 6초 클립 로컬 저장(`canvas.captureStream` + `MediaRecorder`, **부모 게이트 뒤**, 자동 업로드 없음).

### 7.5 카메라
- 섬 허브: 느린 오빗 + 노드 선택 시 돌리 이동(View Transition으로 UI와 동기).
- 스테이지: 고정 디오라마 카메라 + 이벤트 시 줌/팬(방탈출은 방 전환 컷).

## 8. 입력·오디오·음성·저장·PWA

### 8.1 입력
- 모든 조작은 **액션 맵**으로 추상화(`move`, `confirm`, `cancel`, `pick1..4`, `p2.*`…). 재매핑 UI는 부모 패널.
- 포인터: 보이지 않는 큰 히트 프록시(최소 64px 상당)로 레이캐스트, 드래그는 댐핑.
- 키보드는 반드시 `event.code`(한글 입력 모드에서도 동작). 방향키·스페이스 스크롤 방지(`preventDefault`), `touch-action: none`, 더블탭 줌 방지.
- 2P 키맵 프리셋: **A**(P1 `KeyA/S/D/F`, P2 `KeyJ/K/L/Semicolon`), **B**(사용자 지정: P1 `WASD + J/K`, P2 방향키 + `Numpad0`/`NumpadDecimal`). 기본은 B. 키패드 `0`/`.`는 NumLock 꺼짐 시 Insert/Delete로 들어오므로 `preventDefault` + 시작 화면에 "NumLock 켜기" 안내 아이콘. 키 고스팅 점검 화면(부모 패널 "키보드 테스트") 제공.
- 4지선다 UI는 **십자 배치(↑ ← → ↓)**로 두어 방향키·WASD와 공간적으로 일치시킨다.
- 게임패드: 플레이어별 연결 인식, 진동은 지원될 때만.

### 8.2 오디오
- AudioWorklet 합성기: 성공 차임, 웃긴 실패음(고무오리·뿅·뿡), 괴물별 음성(피치·비브라토 파라미터), UI 클릭.
- 절차적 BGM: 스테이지별 스케일/템포 프리셋 + 시드 변주, 문제 풀이 중에는 볼륨 덕킹. BGM·효과음·음성 볼륨 개별 조절. 첫 사용자 제스처에서 `AudioContext` 해제.

### 8.3 저장
- 스키마 버전 + 마이그레이션 + Valibot 검증. 쓰기는 디바운스(500ms) + `pagehide`/`visibilitychange` 즉시 저장.
- 프로필 최대 3개. IndexedDB 불가 시 메모리 폴백 + 부모용 경고. 내보내기/가져오기는 gzip JSON.

### 8.4 PWA
- 전체 프리캐시, 오프라인 완전 동작, 업데이트 시 "새 버전" 안내(아이 화면 방해 금지: 부모 패널에서만 적용 버튼). 플레이 중 Wake Lock, 전체화면 버튼.

## 9. 교육 엔진 (가장 중요)

### 9.1 교육과정 밴드 — 시작점은 **1학년 2학기**, 상한은 **2학년 2학기**
`src/domain/curriculum/curriculum.ts`에 **데이터 테이블**로 두고, 각 레벨에 `verified: 'confirmed' | 'partial' | 'assumed'` 플래그와 근거 메모를 단다. 확인 상태는 `docs/CURRICULUM_VERIFY.md`에 표로 출력(사람이 교과서 차례와 대조할 수 있게).

> 검색으로 확인된 사실: 1학년 2학기에 100까지의 수와 두 자리 수 덧셈·뺄셈이 나오고(받아올림·받아내림 체크리스트 포함 자료 있음), 2학년 1학기 핵심 단원은 세 자리 수·곱셈 등, 2학년 2학기는 네 자리 수·곱셈구구 등이다. 세 자리 수의 덧셈·뺄셈은 3학년 1학기 단원으로 확인된다. **단원 배열은 출판사·개정 시기별로 다르므로** 아래 중 `partial/assumed` 표시를 반드시 교과서 차례로 대조할 것.

| 밴드 | 레벨 | 내용 | 확인 상태 |
|---|---|---|---|
| **0 복습(1-1)** | 0.1 | 9 이내 덧셈·뺄셈, 가르기·모으기 | confirmed (1학기 합 9 이하·한 자리 뺄셈) |
| **A (1-2 기준 시작점)** | A1 | 100까지 수: 자릿값(십·일), 10씩·1씩 뛰어 세기, 크기 비교, 수직선 | confirmed |
| | A2 | 20 이내 받아올림 덧셈, 받아내림 뺄셈(10 만들기·가르기 전략) | partial |
| | A3 | (두 자리) ± (한 자리), 받아올림·내림 없음 → 있음 | partial |
| | A4 | (두 자리) ± (두 자리), 받아올림·내림 없음 | partial |
| | A5 | (두 자리) ± (두 자리), 받아올림·내림 있음, 세로셈 | partial (일부 자료에서 1-2 포함 확인) |
| | A6 | 세 수 덧셈·뺄셈, □ 채우기, 짧은 문장제 | partial |
| **B (2-1)** | B1 | 세 자리 수: 자릿값(백·십·일), 크기 비교, 100씩·10씩 뛰어 세기 | confirmed |
| | B2 | 두 자리 + 두 자리(합이 세 자리) 받아올림 | assumed |
| | B3 | 받아내림 뺄셈 완성, 세 수 계산 | assumed |
| | B4 | 덧셈과 뺄셈의 관계(□ 찾기, 역연산) | partial |
| | B5 | 문장제, 같은 수 반복 덧셈(곱셈 도입 다리) | assumed |
| **C (2-2)** | C1 | 네 자리 수: 자릿값(천·백·십·일), 1000·100·10 뛰어 세기 | confirmed |
| | C2 | 네 자리 수 범위의 백·십 단위 덧셈·뺄셈(예: 1200+300) | assumed |
| | C3 | (세 자리) ± (두 자리), 받아올림·내림 포함 | assumed |
| | C4 | **[선행·도전]** (세 자리) ± (세 자리) — 3-1 단원 근거, 별(★) 도전 표시 | 교과 초과(선행) |
| | C5 | 혼합 세 수, 문장제, 곱셈구구 연계 반복덧셈/뛰어 세기(2~9) | assumed |

- 모든 결과는 **0 이상**, 밴드 C 상한 9999, 합이 상한을 넘으면 생성 거부.
- 부모 패널: "현재 진도"(1-1 … 2-2) 선택 → 시작 레벨·상한 설정. **기본 현재 진도 = 1-2**, 자동 적응으로 C까지 올라갈 수 있음, "선행(C4)" 스위치 기본 켜짐(도전 표시).
- 선택 가능한 학습 범위가 달라도 스테이지 UI는 동일(밴드별 변형은 §11).

### 9.2 스킬 정의
`PLACE_VALUE`, `SKIP_COUNT`, `COMPOSE_10`(가르기·모으기), `ADD_NOCARRY`, `ADD_CARRY`, `SUB_NOBORROW`, `SUB_BORROW`, `THREE_TERM`, `MISSING_TERM`(□), `RELATION`(덧↔뺄 관계), `COMPARE_EXPR`, `ESTIMATE_CLOSE`(목표에 가까운 쪽), `REPEATED_ADD`, `WORD`.
각 레벨은 `{ band, skill[], range, carry: 'none'|'some'|'always', terms: 2|3, qTypes[], representation }`를 가진다. `representation`: `dots | tenframe | blocks | numberline | column`.

### 9.3 문제 생성기 (순수 함수)
```ts
generateQuestion(args: { level: LevelId; skill?: SkillId; rng: Rng; avoid?: QuestionKey[]; constraints?: Constraints }): Question
interface Question { id; skill; level; type; operands: number[]; op: ('+'|'-')[]; answer: number;
  choices?: Choice[]; visual: VisualSpec; hintPlan: HintStep[]; misconceptionMap: Record<number, MisconceptionTag>; }
```
- 최근 10문제와 중복 금지. 6+7(13) 같은 숨은 이벤트 태그 부여.
- **오답 선지는 오개념 기반**: `CARRY_FORGOTTEN`(47+38=75), `BORROW_REVERSED`(52−27=35, 큰 수에서 작은 수 빼기), `OP_CONFUSED`(+↔−), `PLACE_SHIFT`(자리 어긋남), `OFF_BY_TEN/ONE`.
- 스테이지 전용 퍼즐 생성기(폭탄 선 세트, 좀비 카드 손패, 슬라임 역생성, 낚시 목표 등)는 **항상 해결 가능·정답 검증 가능**해야 하며 `solve()`로 교차 검증한다.

### 9.4 적응 난이도
- 스킬별 **BKT(베이지안 지식 추적)**로 숙달도 추정(`pInit, pLearn, pSlip, pGuess` 설정 가능). 목표: 예측 성공률 70~85% 문제 선택(ZPD).
- 승급: 해당 레벨 최근 8회 중 정답률 ≥ 85% 또는 연속 3정답 → 상승. 강등: 연속 2오답 → 한 단계 하강. 강등은 아이에게 "쉬운 코스 열렸어요"로만 표현.
- 간격 복습: 오답 문항·약한 스킬은 FSRS 단순형(안정도·난이도)으로 다음 세션에 재출제. 선택 비율 기본 60% 현재 / 25% 복습 / 15% 도전.
- 응답 시간은 **유창성 지표로만 기록**, 아이에게 압박·표시하지 않음(스테이지 8 기록 제외).
- **배치 놀이**(첫 실행 3~5문제, "괴물 친구 만나기")로 시작 레벨 결정, 이후 연속 보정.

### 9.5 힌트 4단계 (벌칙 없음, 코인 보너스만 감소)
1. **시각**: 점·10칸틀·자릿값 블록·수직선으로 수량 표시
2. **전략**: 10 만들기 / 자릿값 분해 애니메이션
3. **단계 풀이**: 세로셈에서 받아올림·내림 하이라이트 애니메이션
4. **시범 + 재도전**: 같은 유형을 풀어 보여준 뒤 **다른 숫자**로 즉시 재도전(정답 자동 입력 금지)

### 9.6 오답 처리
오답 → 웃긴 연출(1초) → 해당 오개념 태그에 맞는 짧은 시각 피드백(예: 받아올림 점이 올라가는 모션) → 재시도. 같은 개념은 같은 세션 안에 숫자를 바꿔 한 번 더 출제.

## 10. 허브: 3D 숫자섬 (= 스테이지 선택 "맵")

- 둥근 장난감 섬 위에 **8개 스테이지 포털**이 3개 구역으로 배치(막고 부수는 / 모으고 맞추는 / 같이 하는).
- **전부 해제 상태**. 선택은 클릭·탭·방향키·게임패드. 선택 시 카메라가 돌리 이동 + 미니 프리뷰 + 정보 카드.
- 정보 카드: 스테이지 아이콘(3D 미니 모형), 이름, 훈련 스킬 태그(예: 받아올림), 1P/2P 배지, 메달(★0~3), 최고 기록, **"오늘의 추천" 리본**(약한 스킬 기반), 난이도 선택(자동/한 단계 쉽게/한 단계 어렵게), "랜덤 모험" 버튼.
- 섬에는 도감 박물관, 키링 가게, 미션 게시판, 내 집(섬 꾸미기), **부모 문**(문고리 길게 누르기)도 있다.
- 낮/밤은 기기 시계(소프트), 계절 장식은 날짜 기반(Temporal).
- 허브 상단/하단에 **"다음에 얻을 것" 진행 막대**(§12.2)를 항상 표시하고, 섬 중앙에 **성장 나무**를 둔다.

## 11. 스테이지 8종 상세

공통: 한 판 퍼즐 8개(또는 5라운드). 메달 ★1 클리어, ★2 힌트 ≤2, ★3 힌트 0 & 오답 ≤1(시간 무관). 모든 스테이지는 §9 레벨 테이블을 따라 밴드 A/B/C 변형을 지원한다. 큰 수(세·네 자리)는 **자릿값 블록/상자/색 체계**로 표현한다.

**스테이지 튜토리얼 (8개 전부 필수)**: 처음 들어가면 글 설명 없이 15~20초 무언 시연(손 모양 커서가 조작을 보여줌) → 아이가 쉬운 문제 1개를 직접 따라 해 보는 방식. 언제든 건너뛰기 가능, 완료 여부는 `tutorialSeen[stageId]`에 저장, 부모 설정에서 다시 보기. 규칙을 문장으로 길게 설명하는 화면 금지(P4).

### ① 폭탄 해체반
- **디오라마**: 작업대 위 장난감 폭탄, 알록달록 와이어 3~5가닥(색+무늬+숫자 라벨), 느리게 타는 퓨즈(분위기용, 시간 제한 없음).
- **규칙**: 폭탄 숫자 N. 모드 `SUM2`(두 선 합=N), `DIFF2`(두 선 차=N), `SUM3`(세 선 합=N), `PLACE`(자릿값 그룹에서 각 자리 선택). 선을 차례로 탭하면 합/차 계산 연출.
- **밴드**: A N≤100(자릿값 선택 포함), B N 세 자리(백·십·일 와이어 그룹), C 천 단위 퓨즈박스 + 세 자리 와이어.
- **실패**: 폭탄이 부풀어 색종이+고무오리음, 선 위에 계산 그림 자동 표시.
- **성공**: 폭탄이 선물상자로 변신, 코인.
- **수용**: 정답 쌍 ≥1 보장, 모든 오답 쌍은 합≠N 검증.

### ② 좀비 숫자 막기
- **디오라마**: 마당과 집, 3레인, 말랑한 "비틀이" 좀비(무섭지 않게), 머리 위 숫자 풍선, 아래쪽 카드 손패 4장.
- **규칙**: 카드(+k/−k)를 좀비에게 드래그(또는 카드 탭→좀비 탭). 숫자가 0이 되면 풍선이 터지며 쓰러짐. 결과가 음수가 되는 카드는 "안 돼요" 흔들림(카드 소비 X). 카드 사용 후 새 카드 보충, **해결 가능한 조합 항상 최소 1개 보장**.
- **밴드**: A 숫자≤20→≤99, 카드 ±1~9·±10, B 세 자리 좀비·카드 ±100/±10/±1, C 네 자리 + 복합 카드.
- **실패 없음**: 좀비가 집에 닿으면 문이 "쿵" 하고 좀비가 놀라 되돌아감(방어 게이지는 별점 보조 지표일 뿐 게임오버 없음).
- **수용**: 웨이브 3개×좀비 10마리, 속도는 레벨+적응(오답 연속 시 감속).

### ③ 숫자 낚시
- **디오라마**: 연못(TSL 물 셰이더, 물결·굴절·거품), 몸에 숫자가 큰 물고기 6~9마리, 낚싯대와 줄.
- **규칙**: 목표 패널(합 T / 차 T / □+k=T). 물고기 두 마리를 탭하면 낚싯줄이 내려감. 정답이면 낚임, 아니면 튕겨 나감.
- **보너스**: 이상한 물고기(장화·오리·열쇠 모양)가 가끔 지나감 → 탭하면 코인(수학 없음, 쉬는 포인트).
- **밴드**: A 목표≤100, B 목표 세 자리(물고기 숫자는 십·백 단위 혼합), C 네 자리 목표 + 100 단위 물고기.
- **연출**: 잔잔한 BGM, 낚이는 순간 물방울 파티클.

### ④ 슬라임 합체
- **디오라마**: 젤리 놀이판(트레이), 숫자 슬라임 5~7마리 + 빼기 슬라임(붉은, −k). 젤리 버텍스 스프링 + (선택) 장식 물리.
- **규칙**: 슬라임 A를 B 위로 드래그 → 합체(A+B), 크기 증가. 빼기 슬라임을 올리면 상대가 n−k로 줄며 k개 미니 슬라임이 튀어나와 사라짐(시각적 뺄셈). 결과 음수는 튕겨 나감. **되돌리기 무제한·무료.**
- **목표**: 필드에 목표 숫자 슬라임 1마리 만들기(또는 전부 합쳐 하나).
- **밴드**: A ≤99, B 세 자리(슬라임은 자릿값 색 알갱이로 구성), C 네 자리(천 슬라임=금색).
- **수용**: 퍼즐은 **목표에서 역생성**하여 해결 가능 보장, 해답 단계 수 기록.

### ⑤ 이상한 자물쇠 방탈출
- **디오라마**: 장난감 방 5종(주방·서재·다락·정원·보물방) + 번호 다이얼 3D 자물쇠, 방 전환 컷, 갇힌 괴물 친구를 구하는 짧은 이야기(나레이션 TTS, 스킵 가능).
- **규칙**: 방 안 오브젝트 4~6개를 눌러 단서(물건 그룹 그림·□ 식·가르기 그림)를 얻고, 자물쇠 다이얼로 코드 입력. 최소 단서만 찾아도 풀리도록 보장.
- **밴드**: A 코드 1~2자리, B 3자리, C 4자리(자리별 작은 문제).
- **힌트**: 괴물 친구가 단서 오브젝트를 반짝이게 함.
- **수용**: 한 판 방 3~5개, 마지막 방은 보스 자물쇠(두 단계 계산).

### ⑥ 피자 가게 둘이서 (1P+봇 / 2P)
- **디오라마**: 카운터, 오븐, 컨베이어, 상자 포장대. **역할 분담: 굽는이(덧셈) / 담는이(뺄셈)**.
- **규칙**: 주문 N조각. 굽는이는 토핑별 개수(a+b)를 구워 합계를 맞추고, 담는이는 상자에 담은 수와 주문 수의 **차(모자란/남는 수)**를 계산해 입력 → 굽는이에게 전달. 실수는 웃긴 고장 연출.
- **밴드(단위 상자)**: A 낱개 ≤20~99, B **10조각 상자(십)+낱개(일)**, 주문 세 자리는 **백 단위 특대 상자**, C 천 단위는 컨테이너 상자 연출.
- **1P**: 파트너 봇 괴물 직원이 반대 역할(실수 확률 설정).
- **2P**: 같은 화면. 키보드 프리셋 B, 게임패드, 터치 좌/우 분할. 협동 보너스 코인 ×1.5.
- **수용**: 주문 5건, 모든 주문은 정확히 해결 가능.

### ⑦ 숫자 카드 배틀
- **디오라마**: 카드 테이블, 3D 카드 플립, 봇 3종(쉬움·보통·어려움 — 각기 다른 오리지널 괴물).
- **규칙**: 목표 T. 카드 3장 중 2장 선택 + 연산(+/−) 선택 → 결과가 T에 **더 가까운 쪽 승**(차이 계산 = 뺄셈 활용). 5판 3선승. 정확히 T면 퍼펙트.
- **핸디캡(엄마·아빠 모드)**: 어른은 카드 3장 모두 사용(세 수 계산) + 5초 제한, 아이는 여유롭게.
- **밴드**: A T≤100, B 카드 두 자리·T 세 자리, C 세·네 자리 카드.
- **로컬 대결**: 숨김 전환 화면("눈 감아요")으로 카드 비공개.
- **수용**: 음수 결과 연산은 비활성, 라운드 종료 시 계산식을 그림으로 풀어 보여줌.

### ⑧ 정답 달리기 레이스
- **디오라마**: 롤러코스터형 트랙, 오리지널 탈것(로켓/카트), 바나나 껍질, 속도감(FOV·스피드라인).
- **규칙**: 각자 문제 카드(같은 스킬, **다른 숫자**) → 정답 선택 시 부스터, 오답 시 바나나에 미끄러짐(1초, 코인·도감 감소 없음). 결승선은 정답 12개 길이.
- **입력**: 4지선다 십자 배치(키보드 방향키/WASD 직접 선택). 도전 옵션으로 숫자패드 직접 입력.
- **핸디캡**: 플레이어별 **독립 레벨**(부모는 +2 레벨 등), 같은 트랙에서 공정 경쟁.
- **기록**: 이 스테이지만 속도·정확도 기록(별점은 정확도 기준).
- **수용**: 봇 3단계, 2P 로컬(키맵 B / 게임패드 / 터치 분할).

## 12. 메타 진행 (지속성)

- **코인**: 정답 +1(힌트 없이 +2), 클리어 +10/20/30(메달별), 협동 ×1.5. **차감 없음.**
- **먹이**: 정답 3개마다 1개 → 도감에서 괴물에게 준다. 먹이 주기 마이크로 인터랙션 자체가 수학(예: "먹이 12개 중 5개 주면 몇 개 남지?")이며 레벨에 맞춰 난이도 조절.
- **도감(오리지널 괴물 20종 × 진화 3단계 = 60 형태)**: 먹이 5개로 2단계, 12개로 3단계. 라운드 종료 시 괴물 손님 방문(**확률 뽑기 아님**: 3개의 알 중 아이가 고르는 선택, 3판마다 신규 보장, ★3이면 금빛 변이 스킨).
  - 이름 20종 예시: 도니뽀(도넛곰), 쏙쏙이(양말), 뽀송송(버섯), 몽글몽글이(구름), 말랑쿵(젤리), 삐삐톡(로봇), 쿵짝룡(아기공룡), 꽥꽥팡(오리), 꼬물랑(문어), 반짝뿅(별똥), 호박찡, 가시콩, 고구마룽, 치즈콩콩, 우산퐁, 지직이(번개), 눈송이뿌, 바나냥, 피자랑, 두둑이(두더지).
  - 상표·기존 캐릭터와의 겹침을 점검하고 불확실한 이름은 `docs/NAMES_TO_VERIFY.md`에 기록.
  - 괴물마다 모양(파라미터 조합)·색·소리(피치/비브라토)가 다르게 프로시저럴 생성.
- **키링**: 40종, 가방(3D)에 최대 6개 장착·꾸미기.
- **섬 꾸미기**: 16×16 그리드, 60종 오브젝트를 코인으로 구매(게임 내 코인만), 배치·이동·회수 무료, 괴물이 섬을 돌아다님.
- **미션**: 일일 3개(풀 30+종, 로컬 날짜 기준 갱신), 주간 이벤트 1개(데이터 파일로 선언, 시즌 괴물 스킨: 할로윈·겨울 등).
- **소프트 스트릭**: 연속 출석 불꽃. 끊겨도 0으로 떨어지지 않고 "잠든 불꽃 깨우기"로 이어 감.
- **배지 24종**: 교육형(받아올림 마스터, 받아내림 용사, 세 자리 수 탐험가 …), 습관형, 수집형.
- **쉬어요**: 기본 15분마다 20초 눈 운동 연출(부모가 10/15/20/30분/끔 설정).
- **하루 플레이 한도(소프트)**: 기본 40분(초기값, 부모가 조정·끔 가능). 도달하면 "오늘은 여기까지!" 화면 + **내일 받을 보상 예고**를 보여주고, 스테이지 시작만 잠김(섬 구경·꾸미기·도감은 가능). 부모 게이트로 연장.
- **아바타(로블록스풍 꾸미기)**: 머리·옷·모자·등 장식·표정·이동 이펙트 6부위, 합계 60종 이상. 코인·랭크·미션 보상으로 해제. 허브 섬에서 아바타가 직접 걸어 다니고 포털로 들어간다. 같은 기기의 다른 프로필은 NPC 이웃으로 등장(로컬).
- **탐험대원 6종(브롤풍 개성)**: 오리지널 캐릭터 6종, 각자 연출형 패시브만 가진다(예: 정답 때 터지는 효과 종류, 낚시의 이상한 물고기 출현 빈도). **판정·정답·코인 획득량에는 영향 없음**(공정성, P5).
- **트로피·랭크(브롤풍, 감소 없음)**: 스테이지 플레이마다 별 수에 따라 트로피 +1~+5. 누적 트로피로 랭크 8단계(오리지널 이름: 새싹→…→숫자왕) 승급. 랭크 보상은 아바타 아이템·섬 구역 확장. **트로피는 절대 줄지 않는다(P2).**

### 12.1 경제 밸런스 (초기 설계 목표 — 검증 전 추정치, 플레이테스트로 조정)
모든 수치는 `src/domain/balance.ts` 한 곳에 모은다.
- 목표: 하루 15분 플레이 기준 7일 동안 새 괴물 8~10종, 섬 오브젝트 5~8개, 키링 3~5개. 도감 60형태의 약 60%는 한 달 안에, 100%는 두 달 이상 걸리게 한다(너무 빨리 끝나면 지속성이 무너짐).
- 가격 초안: 섬 오브젝트 3단(소 30~60 / 중 100~200 / 대 300~500 코인), 키링 80~150. 하루 평균 획득 코인은 약 120~180이 되도록 정답·클리어 보상을 맞춘다.
- `tools/sim-economy.ts`: 가상 플레이어(하루 15분, 정답률 70/85%)로 7일·30일을 시뮬레이션해 위 목표 범위를 벗어나면 실패시킨다.

### 12.2 성취감·기대감 설계 (필수)
**성취감 — "내가 해냈다"를 눈으로 보여준다**
- **결과 화면 3요소(모든 스테이지 공통, 순서 고정)**: ① 별이 하나씩 터지는 순차 연출 ② **"이번에 새로 해낸 것" 한 줄**(예: "받아올림 문제 첫 성공!", "지난번보다 힌트 없이 2문제 더!") ③ **다음 목표 1개 미리보기**(§기대감).
- **성장 나무**: 섬 중앙에 "숫자 나무"가 있고, 스킬(받아올림·받아내림·자릿값 등)마다 가지가 자란다. 숙달도가 오르면 가지에 열매·꽃이 피고, 아이가 직접 물을 주듯 탭해 확인한다. 비교 대상은 **과거의 나뿐**(친구·타인 순위 금지).
- **첫 성공 세리머니**: 새 스킬 첫 정답, 레벨 승급, 신기록, 도감 진화 때 각기 다른 큰 연출(2~3초, 건너뛰기 가능, 광과민성 기준 준수 §14). 승급은 "새 코스가 열렸어요!"로 표현(§9.4).
- **노력·전략 칭찬**: 힌트를 쓰고 맞힌 경우, 틀린 뒤 다시 성공한 경우도 칭찬한다("끝까지 해봤구나!", "10 만들기 방법 멋졌어!"). 힌트 사용을 부끄럽게 만드는 문구·연출 금지. 칭찬 문구는 40종 이상 풀에서 최근 8개와 겹치지 않게 선택한다.
- **자랑 카드**: 부모 게이트 뒤에서 "이번 주 해낸 일" 카드(이미지)를 로컬로 저장해 가족에게 보여줄 수 있다. 자동 업로드 없음.
- **섬에 남는 흔적**: 해낸 일이 섬의 건물·괴물·트로피 전시로 영구히 남는다(없어지지 않음).

**기대감 — 확실히 올 좋은 일을 미리 보여준다**
- **다음 보상 미리보기**: 허브 화면에 항상 "다음에 얻을 것" 1~2개(진화까지 먹이 n/12, 다음 랭크까지 트로피 n/N, 알 부화까지 n판)를 진행 막대로 표시한다.
- **알 부화 연출**: 알은 "3판 하면 부화"처럼 **플레이 진행 기반**으로 부화한다(실시간 대기 타이머 금지). 부화 직전 알이 흔들리고 금이 가는 2~3초 예고 연출 후 공개한다.
- **미획득 괴물 실루엣**: 도감에서 못 만난 괴물은 실루엣 + 만날 수 있는 곳 힌트("낚시터에 숨어 있어요")를 보여준다.
- **구슬 모으기 → 숫자 축제**: 스테이지 ★ 합산으로 숫자 구슬을 모으고, 8개가 차면 섬에서 불꽃놀이 "숫자 축제"가 열린다(챕터식 큰 이벤트, 이후 새 축제 테마로 반복).
- **내일 예고**: 세션 종료·하루 한도 도달 시 "내일은 ○○ 알이 부화해요", "이번 주 이벤트: ○○ 괴물 등장" 같은 **확정된** 예고만 보여준다.
- **스테이지 입장 전 보상 힌트**: 정보 카드에 "★3이면 금빛 알" 같은 확정 보상을 표시한다.
- **기대감의 윤리 규칙(위반 금지)**: 변동확률 보상(도박형)·가짜 긴급성(FOMO)·사라지는 보상·카운트다운 압박·스트릭 상실 공포 연출을 쓰지 않는다. 기대감은 **예측 가능한 보상의 예고와 선택**으로만 만든다.

## 17. 테스트·품질 게이트

- `pnpm check` = typecheck + lint + 경계 검사 + 단위/속성 테스트 + 오프라인 검사.
- **속성 테스트(fast-check, 시드 고정)**: 전 레벨 1만 문항 — 정답 일치, 범위, 음수 0, 선지 유일성, 오개념 매핑 유효성, 같은 시드 재현성.
- **스테이지 생성기**: 모든 퍼즐 `solve()` 교차 검증, 해결 불가 0.
- **적응 엔진 시뮬레이션**: 가상 학습자(스킬별 정답률 p)가 N문항 안에 기대 레벨로 수렴하는지.
- **리플레이 테스트**: 기록된 입력으로 8개 스테이지의 최종 상태 스냅샷 비교.
- **e2e(Playwright)**: 부팅 → 허브 → 스테이지 완료 → 결과 → 새로고침 후 저장 유지, WebGPU 및 `?renderer=webgl` 양쪽. 8개 스테이지 스크린샷 비교(허용 오차). CI에서 소프트웨어 렌더러 사용 시 시각 비교 임계는 완화.
- **성능 예산**: 초기 JS(gzip) 예산은 측정 후 `size-limit`에 고정(스테이지별 청크 지연 로드), 총 정적 자산 합리적 상한, 드로콜 400 이내 목표, 메모리 누수 테스트(스테이지 20회 반복 입·퇴장 후 힙/텍스처 증가 없음).
