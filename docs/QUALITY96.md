## 0. 정직한 전제 (반드시 지킬 것)

1. **96점은 선언하는 것이 아니라 증거로 증명하는 것**입니다. 점수는 아래 루브릭의 합이고, **증거 파일(테스트 출력·스크린샷·수치·로그)이 없는 항목은 0점**입니다. 자기 채점 부풀리기는 이 프로젝트에서 가장 큰 실패입니다.
2. 재미·애착·재방문 같은 항목은 **코드만으로 측정할 수 없습니다.** 이런 항목은 `HUMAN`으로 표시했고, 부모가 아이를 직접 관찰해 입력해야 점수가 인정됩니다. Claude Code는 `HUMAN` 항목을 스스로 채점하지 마세요. 대신 **사람이 쉽게 측정·입력할 수 있는 도구와 시트**를 만드세요(§7).
3. 점수는 **두 단계**로 확정합니다.
   - **에이전트 게이트**: 모든 비-`HUMAN` 항목 합계가 해당 축의 비-`HUMAN` 만점의 **97% 이상**이고, 각 항목이 자기 배점의 **90% 이상**.
   - **사람 게이트**: `HUMAN` 항목이 입력된 뒤 축 합계 **96 이상**.
4. 이 루브릭의 배점과 임계값은 **설계 목표**이며 실측 통계가 아닙니다. 합리적 이유가 있으면 조정하되 `DECISIONS.md`에 근거를 적으세요.
5. **실행 환경 제약**: Claude Code가 GPU 없는 컨테이너/헤드리스에서 실행되면 WebGPU 실기 검증(S3 일부), 프레임 타임(F6), 로딩 시간(S5의 TTI)을 신뢰할 수 있게 측정할 수 없습니다. 이 경우 해당 부분은 `HUMAN`으로 취급하고, 사용자 기기에서 `pnpm bench`를 실행해 JSON 결과를 `docs/HUMAN_INPUT.md`에 붙여 넣게 하세요. 해당 배점은 §2 표에서 비-HUMAN → HUMAN으로 이동합니다(`check:score`가 환경을 감지해 표시).

## 4. 96점을 만드는 핵심 레버

### 4.1 범위 통제 (품질을 얕게 펴 바르지 않기)
- **Gold Slice 먼저**: 허브 + 스테이지 3개(③ 낚시, ① 폭탄, ④ 슬라임)를 **전 축 96 수준**으로 끝낸 뒤, 같은 템플릿으로 나머지 5개를 확장합니다. 이 3개는 구현이 가장 결정적이라 템플릿이 됩니다.
- 새 기능을 추가하기 전에 **기존 항목의 최저점 3개를 먼저 올립니다**(§6).

### 4.2 에셋·이미지 정책 v2 (흥미성의 가장 큰 지렛대)

**전제**: Claude Code에는 이미지를 직접 *생성*하는 기본 기능이 없습니다(이미지를 *보는* 것은 가능). 이미지는 아래 세 경로를 **우선순위대로** 사용하고, 어느 경로에서도 작업을 멈추지 마세요.
1. **사용자 제공 이미지 (`assets/inbox/`)**: 사용자가 이미지 생성 도구(예: Codex)로 만든 오리지널 이미지를 이 폴더에 넣으면, `tools/ingest-images.ts`로 검증(파일명 규칙·해상도·알파·용량)·최적화(WebP/AVIF)·`docs/ASSETS.md` 등록 후 사용합니다.
2. **연결된 이미지 생성 도구**: 세션에 이미지 생성 도구(MCP 등)가 연결되어 있으면 그 도구로 생성하되 아래 생성 규칙을 따릅니다.
3. **SVG·Canvas·프로시저럴 폴백**: 위 두 경로가 없으면 직접 SVG/Canvas/셰이더로 만듭니다(괴물은 파라미터형 SVG 부품 조합 + 3D 텍스처·데칼 등). Playwright로 렌더해 `Read`로 확인하며 `art-reviewer`와 함께 다듬습니다.

**이미지 주문서**: 경로 1을 위해 `docs/IMAGE_REQUESTS.md`를 생성하세요(`pnpm images:requests`). 항목마다 `파일명 / 용도 / 크기 / 투명 배경 여부 / 스타일 접두어를 포함한 생성 프롬프트 / 금지 요소`를 적습니다. 사용자가 이 표를 이미지 생성 도구에 그대로 붙여 넣고 결과물을 `assets/inbox/`에 넣습니다. 이미지가 아직 없을 때는 임시 SVG 플레이스홀더로 개발을 계속하고, 이미지가 들어오면 교체합니다(교체해도 레이아웃이 깨지지 않게 크기·앵커 규약을 고정).

**필요 이미지 (초안)**: 괴물 컨셉 시트·도감 일러스트 카드(20종 × 진화 3단계 = 60장)·표정 스프라이트, 아이콘(키링 40, 아바타 아이템 60+, 배지 24, 섬 오브젝트 60, 스테이지 포털 8), 스테이지 배경·하늘·디오라마 텍스처, 방탈출 이야기 컷, 세계관 인트로, 자랑 카드 프레임, PWA 아이콘.

**생성·수입 규칙 (경로 1·2 공통)**
  1. 스타일 고정: `ART_BIBLE.md`의 "스타일 프롬프트 접두어"를 모든 생성에 동일하게 사용.
  2. **이미지 안에 글자·숫자를 넣지 않는다**(한글이 깨지기 쉬움). 텍스트는 인게임/UI에서 렌더링.
  3. 투명 배경 스프라이트는 알파 채널 확인, 워터마크·서명·UI 흔적 없음(`ingest-images`가 검사).
  4. 기존 캐릭터·브랜드·실존 인물·유명 작품과 닮은 결과는 폐기하고 재생성. 한 장씩 `docs/IMAGE_REVIEW.md` 체크리스트로 확인.
  5. 기록: `docs/ASSETS.md`에 출처(사용자 제공/도구명/직접 제작)·프롬프트·생성일·파일 해시.
  6. 최적화·용량: WebP/AVIF 변환, 아틀라스화, 해상도 표준(아이콘 512 / 스프라이트 1024 / 배경 2048 등)과 용량 예산을 `ART_BIBLE.md`에 고정.

**3D 모델**은 프로시저럴을 유지합니다(스타일 일관성·용량·애니메이션). 이미지는 텍스처·데칼·표정으로 입혀 완성도를 올립니다.

**사운드·기타**
- 사운드는 WebAudio 합성이 기본. **CC0 또는 퍼블릭도메인**임이 확실한 효과음·HDRI 등은 번들 가능. 출처 URL·라이선스 원문 링크·취득일·해시를 `docs/ASSETS.md`에 기록하고, 출처·라이선스가 불명확하거나 표기(attribution) 의무가 있는 것은 **사용 금지**.
- 런타임 네트워크 호출은 여전히 금지(모든 에셋은 번들에 포함).
- **캐릭터·괴물·아바타는 전부 오리지널**(실존 IP와 닮지 않게).

### 4.3 아트 바이블 (M2에서 먼저 작성: `docs/ART_BIBLE.md`)
팔레트(주색 5·보조 5·금지색), 형태 언어(최소 라운드 반경·외곽선 두께), 라이팅 프리셋 3종, 카메라 규칙, 타이포 스케일(숫자 전용 스타일 포함), 모션 곡선(스프링 파라미터), UI 컴포넌트 상태 규칙, 괴물 실루엣 설계 규칙(20종이 서로 다른 큰 형태를 가질 것), **이미지 생성용 스타일 프롬프트 접두어·금지 요소 목록·해상도/용량 표준**. 이후 모든 시각 작업은 이 문서를 근거로 리뷰합니다.

### 4.4 스크린샷 리뷰 루프 (F1, F7)
Playwright로 스테이지·UI 상태를 캡처 → `art-reviewer` 서브에이전트(스크린샷을 `Read`로 직접 보고 평가)에게 맡겨 "아이가 보고 바로 이해되는가, 어색하거나 싸구려로 보이는 곳은 어디인가"를 비판 → 수정 → 재캡처. 스테이지마다 최소 3회 반복하고 전후 이미지를 `docs/review/`에 남깁니다.

### 4.5 사운드 마스터리스트 (`docs/SOUND_LIST.md`, F4)
스테이지별 BGM 1개 + SFX 목록(정답·오답·시그니처·UI·괴물 음성)을 먼저 작성하고, 구현 상태를 체크합니다. 믹싱 규칙: 마스터 클리핑 0, 효과음 간 상대 음량 표, 문제 풀이 중 BGM 덕킹, 연속 재생 시 반복 피로를 줄이는 변주.

### 4.6 봇 플레이어 (`tools/autoplayer/`, G3·G4·P2·P8 근거)
정책 인터페이스(정답률 파라미터, 반응 지연, 전략 A/B)로 8개 스테이지를 자동 플레이하는 봇을 만들고, 난이도 곡선·경제·클리어 가능성을 대량 시뮬레이션합니다. 결과 표는 `SCORECARD.md`에 첨부합니다.

### 4.7 콘텐츠 볼륨 체감 (P1)
도감 60형태는 단순 색 바꾸기가 아니라 **실루엣이 다른 20종 × 진화마다 눈에 띄는 변화**로 구성합니다. 스테이지마다 배경 테마 3종(시간대·계절)을 둬 반복 피로를 줄입니다.

## 5. 스테이지별 "시그니처 순간" (F5 필수, 스테이지당 1개 + 전용 SFX)

| 스테이지 | 시그니처 순간 |
|---|---|
| ① 폭탄 해체반 | 마지막 선을 자르는 순간 0.3초 슬로모션 → 폭탄이 선물상자로 변신 |
| ② 좀비 숫자 막기 | 풍선이 0이 되며 "뿅" → 좀비가 친구로 변해 손을 흔듦(무섭지 않게) |
| ③ 숫자 낚시 | 줄이 팽팽해지고 물고기가 포물선으로 점프, 물방울 슬로모션 |
| ④ 슬라임 합체 | 합체 순간 젤리가 출렁이며 오버슈트 후 안착(크기 쾌감) |
| ⑤ 이상한 자물쇠 방탈출 | 다이얼이 맞는 "철컥" + 문이 열리며 빛, 갇힌 괴물 친구 구출 |
| ⑥ 피자 가게 둘이서 | 상자가 닫히며 손님 괴물 환호 + 협동 하이파이브 연출 |
| ⑦ 숫자 카드 배틀 | 카드 플립 대결 공개 순간, 퍼펙트 시 특별 이펙트 |
| ⑧ 정답 달리기 레이스 | 부스터 점화와 함께 시야 확장(FOV)·스피드라인, 결승 테이프 |

각 스테이지는 추가로 **웃긴 실패 연출 1종 이상**과 **튜토리얼**을 갖습니다.

## 6. Q-게이트와 개선 루프 (모든 마일스톤 끝에 실행)

1. **채점**: `SCORECARD.md`를 갱신합니다. 각 항목에 점수·증거 경로·측정값을 적습니다. 증거가 없으면 0점.
2. **적대적 리뷰 패스**: `adversarial-reviewer` 서브에이전트(로드되지 않았으면 general-purpose 서브에이전트에 같은 지시)에게 "이 결과물 때문에 손해를 보는 입장"의 비판적 리뷰어로 채점이 과한 항목을 찾아 깎게 합니다. 구현자가 자기 점수를 직접 확정하지 않습니다. 부풀려진 점수를 발견하면 `DECISIONS.md`에 기록합니다.
3. **최저 3개 개선**: 점수가 낮은 항목 3개를 골라 개선합니다(§4 레버 사용).
4. **재채점**: 개선 후 다시 채점합니다. 마일스톤당 최대 5회 반복. 5회 후에도 에이전트 게이트 미달이면 원인과 대안을 `GAPS.md`에 쓰고 사람에게 보고합니다.
5. **스테이지 DoD**: 각 스테이지는 G1·G2·G3·F3·F4·F5·A1과 자기 밴드(A/B/C)의 E-변형 테스트를 통과해야 완료입니다.
6. 이전 마일스톤 항목의 점수가 **하락(회귀)** 하면 새 작업보다 먼저 복구합니다.

`pnpm check:score`: 루브릭 합계 검증, 증거 파일 존재 확인, 자동 항목 재실행, 회귀 감지.

## 7. 사람 게이트 키트 (Claude Code가 만들 것)

사람이 **아이를 직접 관찰해 입력**하는 항목(HUMAN)을 쉽게 처리하도록 다음을 만드세요.
- `docs/HUMAN_INPUT.md`: 항목별 입력란(날짜·관찰자·값·메모). 비어 있는 항목은 0점으로 계산.
- 부모 패널의 **관찰 도우미**: 세션 길이, "한 판 더" 선택 횟수, 막힌 지점 로그, 재방문 일수를 로컬 기록에서 자동 집계해 표로 보여줌(외부 전송 금지).
- `docs/PLAYTEST.md`: 아이 앞에서 따라 할 수 있는 순서(준비물·시간·질문 5개·하지 말아야 할 행동). 질문 예: "제일 재미있던 건?", "다음에 또 하고 싶어?", "어디가 어려웠어?" — 유도 질문 금지.
- **이미지 닮음 점검 키트**: `docs/IMAGE_REVIEW.md`에 생성 이미지 전체의 썸네일 시트를 만들어 두고, 부모가 훑어보며 기존 캐릭터·브랜드와 닮아 보이는 것을 표시할 수 있게 함. 표시된 이미지는 폐기·재생성.
- 최종 보고에 "사람이 채워야 하는 항목 목록과 현재 상태"를 표로 포함.
