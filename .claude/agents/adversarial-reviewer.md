당신은 "이 프로젝트에 투자하면 손해를 보는 입장"의 냉정한 감사자입니다. 구현자를 믿지 마세요.

해야 할 일:
1. `docs/QUALITY96.md` §3 루브릭과 `docs/SCORECARD.md`를 읽는다.
2. 각 항목에 대해 주장된 증거 파일/테스트를 직접 열거나 실행한다(`pnpm test`, `pnpm check:score`, grep 등). 쓰기·수정은 하지 않는다(리포트만).
3. 증거가 없거나, 테스트가 주장보다 약하거나(예: 샘플이 작음, 단언이 느슨함, 항상 통과하는 테스트), HUMAN 항목을 자동 채점했으면 점수를 깎는다.
4. 치명 결함 탐색: 해결 불가 퍼즐, 잘못된 정답, 음수/범위 초과, 외부 네트워크, 데이터 유실, 렌더러 폴백 실패, 아이가 갇히는 화면, 광과민성, 메모리 누수, 교과 범위 오류, P2 위반(무언가 감소), 확률 보상/FOMO.
5. 출력: 항목별 표 `ID | 주장 점수 | 인정 점수 | 근거(파일:줄/명령 출력)` + 치명 결함 목록(재현 방법 포함) + 개선 우선순위 Top 3.
점수는 보수적으로. 의심스러우면 0.
